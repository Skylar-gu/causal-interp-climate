# Reproducing the paper's results

For every result in the paper: where it appears, the exact commands in run order, the environment, the cost, what each step
reads (shipped in `results/` | regenerated by a command here | external asset) and what it writes.

Two levels of reproduction are possible, and the table is honest about which is which:

* **From the shipped result files (CPU, minutes).** Every figure and table in the paper is
  regenerated from `results/`, `data/` and the bundles in `results/*_inputs.npy` by the
  `figures/paper_fig_*.py` scripts and `notebooks/demo.ipynb`. No GPU, no external data.
* **From scratch (GPU, hours to days per experiment).** The `graphcast_sae` scripts re-run the
  interventions. They need the DeepMind GraphCast checkpoint, WeatherBench2 ERA5 streamed from
  the public bucket, one ~46 GB GPU, and for most analyses the 6.7 GB i.i.d. activation dump
  (regenerated once by `extraction/extract_iid_dump.py`). A few curated inputs were produced by
  the main analysis pipeline that is not part of this package; they are listed at the end and
  ship as-is.

Paper locations are given by LaTeX label (`fig:contrast`, `tab:mechanism-interventions`, …)
because figure numbers move between drafts. Runtimes are those observed on one 46 GB GPU
(Ada-class) and are approximate.

## Environment

* **Demo / figures / CPU analyses — Python 3.9**: `pip install -r requirements.txt` (skip the
  commented GPU block). Add `pip install -r requirements-dev.txt` for `pytest` and the notebook
  runner. Everything marked *demo env* below runs here in minutes.
* **GPU experiments — Python 3.11 "JAX env"**: `jax[cuda12]`, `dm-haiku`, `graphcast`
  (`pip install "graphcast @ git+https://github.com/google-deepmind/graphcast.git"`), `xarray`,
  `zarr`, `gcsfs`, `cartopy`; the versions used are listed in the GPU block of `requirements.txt`.
  Everything marked *JAX env* runs here; *JAX env, CPU* needs no GPU but does need `graphcast`.
* **torch env**: the three CPU catalog scripts that use `torch` (`atlas/feature_select.py`,
  `obsgraph/build_pool.py`, `extraction/fs_catalog.py`) run in the Python 3.9 environment with
  `torch==2.6.0`.
* **Locations** are resolved in `graphcast_sae/paths.py`; set
  `GRAPHCAST_PARAMS` (DeepMind 0.25°/37-level checkpoint), `GRAPHCAST_ASSETS` (the release's
  `stats/`), and `GC_SCRATCH` (where the regenerable dumps go; default `scratch/`, git-ignored).
  WeatherBench2 is streamed anonymously from `gs://weatherbench2/...`; nothing is mirrored.
* Scripts are run from the repository root as `python -m graphcast_sae.<group>.<script>`;
  figure builders as `python figures/<name>.py`.
* `python -m pytest tests -q` checks the package imports, the path resolution and the path
  hygiene (no machine-specific paths); `tests/mediation_selftest.py` is the CPU exactness
  test of the mediation clamp (JAX env, ~3 s).

## The i.i.d. activation dump (needed by most CPU analyses)
`FS_DEVICE=gpu XLA_PYTHON_CLIENT_PREALLOCATE=false python -m graphcast_sae.extraction.extract_iid_dump --n 160` → `$GC_SCRATCH/fs_iid_dump.npy` (160 windows × 40,962 nodes × 512, fp16, 6.7 GB) + `fs_iid_meta.json`; ~4 s per window on the GPU plus WB2 streaming. The mesh geometry it pairs with ships as `data/mesh_2to6_geom.npy`.
